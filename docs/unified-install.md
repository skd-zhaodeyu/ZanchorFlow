# 同一个包，直接安装

把本源码包交给当前Agent，说“安装这个skill”即可。执行安装的Agent应先运行本仓库tools/install.py，不直接猜测宿主，也不把整个仓库复制进技能目录。不要求用户选择宿主或输入区别指令。

## 安装者执行顺序

1. 使用当前宿主已有Python，在独立项目E盘work目录准备安装工作区。不要自动安装依赖。
2. 执行 python -B tools/install.py inspect --work <绝对工作目录>。工具读取当前进程标记与启动链；不依据同机安装目录或无关进程选择宿主。
3. 若当前工具环境明确提供持久、可写的技能搜索根目录，可将其记录到工作区runtime-context.json：{"skill_roots":[{"path":"绝对路径","source":"runtime_catalog","persistent":true,"writable":true}]}。这是当前运行环境信息，不是用户的宿主选择；不要凭目录存在虚构注册关系。需要时用--context指向此文件。Codex的既有CODEX_HOME/skills或~/.codex/skills也可由工具自动确认。
4. 执行 python -B tools/install.py prepare --work <工作目录> [--context <上下文文件>]。工具生成安装视图和逐文件差异证明。
5. 目标位置已明确且用户确实请求安装时，执行 python -B tools/install.py install --work <工作目录> [--context <上下文文件>]。如果工具报告身份冲突、目标未知或多目标，停止，不猜测、不绕过。安装成功后复核输出收据和文件哈希，再告知用户。

不提供--host或--force开关。不要把自己模型的名字当宿主，不把转发报告当当前运行上下文。

## 安装选择

- 明确Codex：原始完整版，安装文件与原dist/zanchorflow.zip逐字节一致。
- 明确千问或WorkBuddy：同名zanchorflow的Image Layer安装视图，Style DNA及所有质量门槛完整保留。
- 其他宿主、无充分身份依据：默认原始完整版，不限制Magic Layer；不表示已验证该宿主的外部工具。
- 相互冲突的当前身份依据：停止，零安装写入。

运行时不重新识别宿主。Codex和默认完整版中没有安装器、宿主配置或限定说明。两宿主只改变安装视图的路线选择与工具接线，不修改八份规范或视觉、文字、封页与合并要求。

## 依据与限制

工具把当前进程的Codex会话标记及实际启动祖先的可执行路径作为身份依据。其他Agent运行进程只作无关环境，不参与选择。上下文文件不能指定宿主或覆盖识别。模型自报、目录名、转发文本不构成身份依据。没有足够证据就完整安装，不能因为缺少Codex标记而限制。

工具不主动调用任何生图、消字、Canva或分层接口，也不改环境变量、依赖或现有任务状态。默认只准备、验证；install动作才写目标目录。安装失败采用备份与回滚，不静默删除旧版本。安装收据和备份在技能目录之外。

本流程的目标位置登记来自当前运行环境；它不是防恶意伪造上下文的安全边界。确认不了当前宿主的持久技能根目录就停止，不把临时插件缓存当作安装位置。若宿主提供原生安装API而不能登记文件系统目标，先prepare再按其受支持流程导入生成的目录并逐文件复核；不擅自宣称安装成功。

## 中断恢复与开发验证

安装事务先持久记录收据，再移动旧目录。普通失败立即回滚；进程被强制终止后，下次同一宿主安装只在旧进程确认结束、记录与哈希匹配时恢复，并保留中断的新目录和旧版。正在执行、上下文变化、无法确认的锁或哈希变化均停止，不强制抢锁。

开发测试：`python -B -m pytest tools/install_tests -q -p no:cacheprovider --basetemp <E盘独立work目录>`。模型决策评测、模拟身份安装、真实宿主识别分别记录。原技能安装文件不包含这些开发文件。根 README 和开发差异保护助手的明确变化由 tools/install_scope.py 逐字节还原，随后继续原有历史断言；没有放宽运行文件或质量门槛。


当前交付为 **V1.0**；包名和调用名不变，同版本更新以内部更新时间区分。Image Layer 按编辑价值选框，差结果如实记录且不自动重新分层。包内版本、安装版本和哈希可用安装器核对；历史 RC 信息只用于来源追溯。
